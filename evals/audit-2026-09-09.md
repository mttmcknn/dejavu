# Skill audit on September 9, 2026

Scope: the four DejaVu skills, their portable distribution and their evaluations in this repo.
Personal/global skills are not modified. Baseline: repository commit `9142685`,
skill bundle 0.2.0. Revised bundle: 0.3.0; the library remains 0.6.0-SNAPSHOT.

## Findings and corrections

| Finding in old skills | Effect | Revision and evaluation coverage |
|---|---|---|
| Performance floor equals number of state sources | False diagnoses under batched/coalesced writes | Measure executions and UI outcomes; `perf-batched-state-novel` |
| Always converge to exact counts; never retain atMost | Changes a valid user budget and keeps optimizing passing code | Preserve contract and stop when satisfied; `perf-budget-negative` |
| First matching diagnostic row determines cause | Dirty bits/equal counts become unjustified certainty | Source-backed hypotheses, truthful stability contracts; `triage-dirty-bits-novel` |
| Automatically optimize when a test budget fails | Can destroy intentional library fixtures | Preserve independent oracle and expected errors; accuracy and expected-error controls |
| Always ask whether to augment existing tests | Blocks already authorized edits | Augment relevant tests by default; `writer-augment-direct` |
| Relative docs assumed in every consuming project | Globally installed plugin lacks required guidance | Bundle setup/API references and test portable links; consumer routing case |
| Stable-only onboarding test | Can pass when tracking is disabled | Require UI change plus positive tracking evidence; Android direct case |
| Unconditional wait and clock-host assumptions | Can erase timing regressions or change host unnecessarily | Preserve test lifecycle/clock intent; keyed/Wasm and mixed-lifecycle reviews |
| Broad overlapping trigger descriptions and forced handoffs | Wrong routing and unnecessary work | Narrow descriptions; companions optional; three cross-skill routing cases |
| No Codex repository discovery path | Bundled skills unavailable through standard local discovery | `.agents/skills` links to the same canonical files |

Main skill bodies fell from 774 lines to 216 lines. Two bundled references retain
versioned dependency and API detail. Reduced size is a maintainability observation,
not evidence of better model performance.

## Guidance used

[OpenAI's current Astra prompting guidance](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#prompting-best-practices)
identifies sensitivity to skill instructions, unnecessary clarification and overly
broad verification as behaviors to check. The revisions therefore remove conflicting
mandatory workflows, preserve authorized scope and match checks to the change.

[OpenAI skill documentation](https://learn.chatgpt.com/docs/build-skills) supports
focused jobs, precise triggers, standard discovery and testing activation.
[Anthropic's authoring guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
informs concise domain-specific instructions, bundled progressive references and
model-specific evaluation. These are design inputs; they do not prove this bundle
works on every frontier model.

The evaluator adapts [Chris Banes' methodology and code](https://github.com/chrisbanes/skills/tree/2db11bb412254246bf0a5f6e5e320177107a7c53/evals).
The source-excerpt corpus and single Codex adapter are explicit initial limits.
Adding executable Compose fixtures, held-out immutable source snapshots and a
separately isolated Claude adapter would broaden the evidence, without pretending
that today's harness already measures those dimensions.

## Verification evidence

- Four canonical skill packages, two references, plugin versions and both link
  layouts validated offline.
- All 15 case manifests satisfy coverage, routing and write-scope contracts.
- 92 deterministic harness tests passed, including source-edit/protected-file
  checks, isolated skill staging, default preview, call cap, blinded packets,
  resume fingerprints, scoring, audit sampling and a fake-CLI end-to-end run.
- Historical skill selection and a six-call preview were exercised without
  model calls. CLI available: `codex-cli 0.144.5`.
- All four skills passed the skill-creator validator. The strict MkDocs build
  and 32-page internal-link/anchor checks passed.
- No live model comparison has been run for this audit yet. No behavioral uplift,
  Claude compatibility score, compilation or UI-runtime pass is claimed.

The proposed initial live comparison is one no-change case, three arms, one
repetition, old/current skills, separately under Astra and Terra, with a fixed
judge: 24 calls. It is a compatibility smoke, not a full repeated benchmark.

## Agent-neutral distribution follow-up

Moved the unchanged skill instructions and references into real `skills/` folders.
Both `.agents/skills/` and `.claude/skills/` now link directly to that source;
Claude's plugin consumes it directly. The README and website explain the Skills
CLI, manual copying, updates and the retained marketplace option.

Local packaging smoke used Skills CLI 1.5.25, Node 26.5.0 and a temporary consumer
project. `skills add /absolute/path/to/dejavu --list` discovered exactly four skills.
Installation with `--skill '*' --agent codex claude-code cursor github-copilot
opencode --copy --yes` succeeded. Both installed directory trees contained complete
bundles matching the canonical files byte-for-byte, with no symlinks. `skills list`
reported all four. This verifies installer distribution, not live client activation
or model behavior; those clients were not launched for this check.

Four skill-creator checks, bundle validation, all 15 case contracts, 94 deterministic
tests and the strict 33-page documentation build/link check pass. Regression coverage
now exercises both historical and neutral Git archive layouts and rejects canonical
bundles that depend on external symlinks. No model calls or hosted CI runs were used.
